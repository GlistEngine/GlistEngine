1/*
2 * gVKUserShader.h
3 *
4 * The Vulkan side of gShader: a shader an application wrote, loaded at run time
5 * and addressed by name.
6 *
7 * The two backends disagree about what a shader is. OpenGL compiles GLSL, links
8 * a program, and lets a caller reach any uniform in it by name at any time.
9 * Vulkan has no free-standing uniforms and no linking step: a shader is SPIR-V,
10 * its resources are descriptor sets and push constants, and the layout of both is
11 * fixed when the pipeline is created - together with the vertex layout, the blend
12 * state and the render pass. There is nothing to set a uniform on.
13 *
14 * What closes that gap is reflection. gVKReflect reads the compiled SPIR-V back
15 * and reports every uniform block member by name, offset and shape, so
16 * setVec3("lightpos", v) becomes a write at a known offset into a uniform buffer
17 * the module owns, and setInt("tex", 0) becomes a note that binding N samples
18 * whatever texture unit 0 holds. The application keeps the OpenGL-shaped API it
19 * already uses; the difference stays here.
20 *
21 * What an application has to change: nothing in its C++, but its GLSL has to be
22 * Vulkan GLSL. Loose uniforms are not a thing to translate into - they have to be
23 * gathered into a block with a set and binding, and samplers need a binding of
24 * their own. That is a shader source change, not an engine one, which is why the
25 * failure is reported by name rather than papered over.
26 *
27 * Where the SPIR-V comes from:
28 * - shaderc, when the build has it (desktop development builds). GLSL goes in
29 * as the application wrote it and comes out compiled, hot reload included.
30 * - a .spv file beside the source otherwise, which is every mobile build and
31 * every release. shaderc is a large dependency and is not linked into those,
32 * so the shader is compiled ahead of time by glslc and shipped next to the
33 * GLSL - the same arrangement the engine's own shaders use through
34 * gVKShaders.h.
35 */

56// Shaders the engine builds through this path rather than as a pipeline of its
57// own, and which therefore have to work in a build that links no shader compiler.
58// There is one: gFbo's screen resolve, the pass that ends a post-process chain.
59// Its SPIR-V is compiled at build time from graphics/shaders/vk/fbo.vert and
60// .frag and lives in gVKShaders.h, and is used when compiling is not possible.
61// Anything an application loads has no such fallback and passes NONE.

67// Compiles and builds one shader from GLSL held in memory. sourcePath, when the
68// sources came from files, is where a pre-compiled .spv is looked for; leave it

70// on any failure, having logged why.

89// Writes one value by name. component, rows and columns describe what data
90// points at - a glm::mat4 is FLOAT 4x4, a glm::vec3 is FLOAT 3x1 - and the write
91// is converted into whatever layout the block declared, which is not the same
92// thing: a mat3 is nine tight floats here and three sixteen-byte columns there.
93//
94// Returns false when the shader declares no such name, which is not an error in
95// itself: the OpenGL path silently ignores a uniform the shader optimised away,
96// and this keeps that behaviour rather than making every unused setter fatal.
97bool gvkSetUserShaderValue(gVKUserShaderId id, const std::string& name, const void* data,
98 gVKMemberComponent component, uint32_t rows, uint32_t columns);
